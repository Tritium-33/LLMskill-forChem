# 真实测试后的架构修正

日期：2026-10-10。原始测试版本 `cf65781d`；本轮自有 router 版本 0.5.0。
依据：[三组真实测试与独立盲审](evaluations/2026-10-10-dsh/README.md)。这里记录原因、改动及验证边界，历史回答与评分保持原样。

## 从观测到原因

| 真实观测 | 可支持的原因分析 | 修复位置 |
| --- | --- | --- |
| C 组预期 router 指令未进入实际初始上下文；仅 T1-C 读取 router | 运行器覆盖 DSH_HOME 造成配置与实载不一致；无法把 C/B 当作 router 对照 | 可选运行证据预检；不改写冻结实验，不声称已修复 DSH 本体 |
| T5 占 73.2% token，全部 863 次委派请求都在 T5 | 深度协议与开放式检索的成本高度集中；这不等于已证明技能是唯一原因，网络、宿主和模型也参与 | 按交付目标选择有限对比/深审；复用资料、有限重试、委派边界与收尾 |
| T5-C 持久记录中 8 个子会话仅 1 个有完成终态 | 完成答复与委派状态脱节；不能说全部三组都一样未完成（A/B 状态不同） | 统一交接状态与交付检查；工具识别最终答复之前的终态 |
| T4 三组均超过论文数量上限 | 只约束主列表、放任补充列表，会违反整个答复的用户限制 | 整体答复计数和截止日期检查 |
| 图例/源数据映射、单位、自由能层级、MAE 解释等错误 | 有真实来源并不等于读对或支持附加判断；批评性措辞数量不是准确性 | 论文路线按需加载证据检查，保留条件与不确定性 |
| 有些单技能/无技能回答更好或更省 | 不支持越多技能越好；一次运行无法估计稳定收益 | 最少充分步骤；不加全局质量分数或自动调权 |

这些是观测和有边界的机制分析，不是随机对照的因果结论。仅缩短提示或减少代理，也不能直接宣称科研回答更好。

## 借鉴哪些机制

下列官方项目资料于 2026-10-10 查阅。链接指向上游可变版本，仅借鉴架构思路；没有复制新技能或变更上游正文，也不表示对方为本项目背书。

- **AtomisticSkills** 明确区分直接查询、计算研究和文献综合，不给简单查询自动创建研究工程。借鉴“先判任务范围”，保留本合集自然语言入口；不引入它的专属 Artifact API 或审批流程。[research-standards](https://github.com/learningmatter-mit/AtomisticSkills/blob/main/.agents/rules/research-standards.md)
- **Computational Chemistry Agent Skills** 同时有领域 router 与语义 workflow 规范，并非只有平铺技能。保留领域选择权，通用层只衔接输入、结果、证据与状态；没有为了这些修复另装 taskboard。[官方目录](https://github.com/jinzhezenggroup/computational-chemistry-agent-skills)
- **BootLoops** 的 acceptance-gate 强调完成应有独立、可能失败的检查；不是运行结束就正确。本项目借鉴检查与生成分离、正反控制，科学质量仍交独立评审；没有把数学高精度验收直接套给论文问答。[acceptance-gate](https://github.com/BootLoops-ai/skills/blob/main/skills/acceptance-gate/SKILL.md)
- **Google DeepMind Science Skills** 采用 SKILL.md、scripts、可选 references 的目录结构。本轮沿用按需加载参考文件，不把所有规则塞进每次上下文，也不改安装副本冒充仓库源文件。[官方说明](https://github.com/google-deepmind/science-skills)
- **K-Dense** 将技能的指导、运行依赖、脚本和测试区分记录。本轮保持格式/逻辑检查与科学实测分开；未用它的技能数量或项目名气推断质量。[官方说明](https://github.com/K-Dense-AI/scientific-agent-skills)
- **Anthropic** 的工程经验强调简单组合、实际工具反馈和停止条件。这里采用有限路线与交付检查，不为每个问题强制增加多代理迭代。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

## 实际结构

```text
自然语言问题
  → 自有 router：交付目标与范围 → 一个必要功能索引
  → 具体技能 / 领域 router（保留上游协议）
  → 多步时携带：证据位置、条件、覆盖范围、未解决项、状态
  → 交付检查 → 答复与实际执行记录

旁路：宿主观察记录 → 可选离线检查工具 → 指令/加载/委派状态检查
```

没有新增 UI、用户任务表单、默认 AGENTS 规则、常驻服务、数据库或模型 API。只装一项技能仍然可行，直接调用仍遵循上游自己的要求。

1. **选择层**：自有 `SKILL.md` 改为英文机器指导；中文说明留在 README 和用户目录。先判断用户要的是解释、有限对比还是完整深审，再选择技能。“有什么新意”不再自动等同无限范围的深审；用户明确指定 `lit-review` 或要求完整审查时仍遵循原协议，不能偷减证据义务。
2. **交接层**：共享 `execution-contract.md` 规定范围、交接内容、委派边界和最终交付。没有强制写状态文件；任务状态可以留在上下文。`workflows.json` 引用共享契约并增加完成检查，结构检查器验证引用存在。
3. **证据层**：论文路线按需读取 `evidence-checks.md`，要求“身份真实”“引用支持”“条件可比”分别核查。没有写入被测论文答案或具体数值来提高旧题成绩。
4. **观测层**：`tools/check_run_evidence.py` 接收实际请求和工具事件的整理记录，区分观察到、缺失、无法判断。它是独立可选设施，不会强制 router 被调用，也不替 DSH 导出原始日志。详见 [格式和使用](run-evidence.md)。
5. **回归层**：增加反例测试，确保配置文件不能冒充注入、worker 加载不能冒充主会话加载、最终答复之后的完成不能倒算。新增三道合成论文案例，材料和期望分开管理，尚未运行新的独立模型质量评测。

这比增加一个覆盖所有工具的新引擎更小，但不只是换分类：任务升级条件、阶段交接、失败停止和可观察验收都有明确落点。规则层仍可能被模型忽略；需要严格限额/强制路由时，应由宿主实现控制并用真实请求验证，而不是声称 Markdown 有拦截能力。

## 验证与下一步

本轮验证结果见 [实施记录](architecture-progress.md#2026-10-10-真实测试后的修正)。新增合成案例与旧真实题均用于发现问题，不再作为独立的泛化证明。尚不能宣称 0.5.0 提高准确率、节省 token 或减少耗时。

下一轮实测应先用实际初始请求确认路由指令生效，再用新的论文/问题，维持相同模型、工具、材料与预算，按题进行多次配对运行；记录成功加载、缓存/非缓存/输出、委派请求和总耗时。输出质量继续交给看不到分组、成本和调用轨迹的独立评审。不要同时在执行组里加载本文件或案例期望。

上游更新仍走已有只读监测、许可/差异核对、相关案例检查和显式安装；本次没有自动拉入技能或依据这 21 份回答生成全局技能权重。
