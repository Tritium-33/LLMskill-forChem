## 技能与 router 调用的定量分析

### 计数口径

- **读取/调用事件**：Astra按工具实际读取`SKILL.md`的操作计数；DSH按原始事件流中`tool_call(tool=skill)`计数，并核对对应`tool_result`。仅列目录、答案自述或读取辅助参考文件不计入。
- **不同技能数**：同一组内按技能名去重，包含router。单项技能读取次数不含router，router另列。
- **发生读取的轮次**：只统计当轮新发生的读取事件，不代表技能作用覆盖率。连续会话可以复用前文指令，无法据日志为这种复用分配可靠次数。
- **统计范围**：两边均为三组主会话。DSH B的6个子代理计入此前资源总量，但其内部技能调用未在这里核实；不要把主会话调用数解释为整棵代理树调用总数。

### 与消耗、质量的关联

- Astra的B→C：单项技能读取2→5次，router 0→1次，不同技能2→5项，发生读取的轮次2→3轮；总token增加53.2%。C的Q6新增`lit-review`，扩大前作检索，该题为1,118,019 token、113.894秒；B同题为280,099 token、56.827秒。可以观察到范围扩展及成本增加，不能把差额全部记为该skill或router的直接开销。
- DeepSeek的B→C：单项技能调用4→5次，router 0→1次，不同技能4→6项，发生调用的轮次2→4轮；总token反而减少61.7%。B另有6个子代理且发生延迟交付，说明调用次数与资源开销不呈简单单调关系。
- 两边C都只在Q1实际读取router，后续可沿用上下文。不能把六题都称为“六次router调用”，也不能因为后来未重读就判定没有路由。
- 不计算“每调用一次skill提升多少分”或“单次router耗费多少token”：一轮可能同时含材料阅读、多个技能、检索与推理，且后续轮次持续携带前文。现有记录不能把这些成本和质量贡献独立拆分。
- 结论是**接入成功、选择行为可观察，质量收益仍需结合题目判断**。本轮部分专业性、证据说明和文献覆盖有改善，但“读取更多技能”本身不是质量指标。

### 回答质量的可核对实例

- **DSH A Q5：**把Smith2017说成目标论文参考文献12；实际ref12为Enman2018，Smith为ref32。又把“形成概率高三个数量级”的比较归于Xiao2018，实际对应ref70 Van der Ven2006。可对照[目标论文正文及参考文献](https://www.nature.com/articles/s41467-020-16237-1)。这些错误会影响对论文与前作关系的理解；Astra本轮没有重复这两处归属。
- **DSH B Q5：**最终回答明示“完整的三篇‘研究了什么’将在精读完成后补上”。Q6确实补交，但不能改记成Q5已完整回答。Astra三组在Q5均交付三篇DOI及研究内容。
- **DSH C Q6：**以其他体系已有离子交换，判本文相关陈述“不成立”，混淆“不是首次”与“事实不成立”；将模型晶格吻合直接归为按实测参数筛选，也超出了其给出的证据。批判性规则同样需要约束批评强度。
- **Astra C Q6：**读取 `lit-review` 后扩展前作比较，且限定自己未完成优先权审查；该题消耗1,118,019 token，占本组41.4%。这是可见的信息增量与额外成本，不应直接判为收益或浪费。

质量判断是主代理知晓组别的定性审计，未逐条核实全部36份回答的数值、外部全文及图像，不是独立盲审或专家认证。因此不提供准确率百分比、总评分或模型胜率。

## 适用范围与项目判断

本轮支持把项目定位为“节省搜集和选择技能时间的化学科研合集”，尚不支持承诺省token或普遍提高准确率。router有选择与组织作用，重型综述技能会扩展任务；使用者应依据需求判断新增证据是否值得成本。不同模型对同一技能的执行方式不同，不能把DSH中的单次成本变化泛化。

比较限制：

- 三个Astra子会话不继承父会话历史，也未收到其他组答案；但共享文件系统，没有强制读隔离。宿主技能名称元数据仍可能可见，A仅禁止实际加载技能。DSH也存在宿主技能残留和可读其他会话记录的边界，不能称为完全隔离。
- Astra各组并行，DSH各组顺序；Astra统一禁止再委派，DSH B实际委派6个子代理。这是实际配置比较，不能分离纯模型、router或并行机制的因果效果。
- Astra通过读取技能文件使用技能，DSH通过skill工具；系统提示、工具、网络、缓存与tokenizer不同。DSH有只读沙箱、shell及TLS障碍。不能仅凭总token比率换算费用或纯模型效率。
- 每组是连续六轮，不是六个独立重复实验。后续题受前文、已读材料和累计上下文影响；每条件只跑一次，不作显著性推断。
- Astra正式18题合计5,560,602 token。此前被中断的三个首题尝试已上报966,229 token，单列、不混入；中断时未上报的在途消耗无法补齐。主代理管理与审计用量未计入三组。
