# DOI → 论文分析：默认路线与分支

用于给定 DOI 的单篇论文阅读、结构分析或证据评价。依据目标、已有输入、证据缺口及可用工具决定下一步；不要仅因为有很多文献技能就全部加载。

| 顺序 | 条件与选择 | 交付给下一步 | 未满足条件时 |
| --- | --- | --- | --- |
| 1. 确认论文身份与获取资料 | 只有 DOI 时用 `paper-lookup`，核对 DOI、题名、作者、版本和来源，寻找合法全文与补充材料；用户已给可靠全文时复用 | 元数据、来源 URL、实际取得的文件及版本 | 查无记录则报告失败；只有摘要则限制为摘要分析 |
| 2. 严格书目核验（条件分支） | 用户要求逐字段核验，或元数据冲突时用 `ref-check`；普通身份确认不必再执行一套完整核验 | 经核对的条目及未解决字段 | 保留冲突，不编造页码或作者 |
| 3. 读取证据 | 用 `reading-contract`，实际读取正文、图表和可取得的补充材料，记录页码/章节与证据 | 研究问题、方法、结果、结论及对应位置 | 无全文不声称已读；缺补充材料标记覆盖范围 |
| 4. 分析论文结构 | 普通结构分析沿用阅读结果，由模型说明问题如何引出方法、结果如何支撑结论；不必增加 skill | 文章结构与论证关系 | 区分原文事实与解释 |
| 5. 扩展分析（条件分支） | 评价方法和证据时用 `scientific-critical-thinking`；研究写法/改写稿件时才考虑 `scientific-writing`；创新性对比才用 `lit-review`，多篇综述才考虑 `literature-review` | 对应目标的分析与依据 | 新增检索范围会明显扩张时说明范围；不要从单篇阅读自动升级为全面综述 |
| 6. 交付 | 汇总本轮真实技能与完整操作顺序作为前缀，再给论文分析 | 可追溯结果及未完成项 | 不把“选中技能”“读到文件”写成“已验证科学结论” |

开始时简短给出计划与分支触发条件，不必提前读取所有候选技能。后续根据实际获得的材料调整计划，说明新增/跳过步骤的可观察原因（例如无全文、书目冲突、用户要求评价证据）。这些是公开的操作依据，不是内部思维链。

检索记录、论文全文和页码证据在技能间复用；同一轮已读取的指导不必无故重读。明确每步输入、工具、产物和状态。最终前缀中的技能清单只收录实际使用项；未执行的计划步骤标明未执行，不列为已调用。

## 示意输出（不是执行记录）

```text
【本轮技能】paper-lookup（检索）；reading-contract（原文阅读）
【执行步骤】
1. [完成] 读取 paper-lookup 指导，用 DOI 查询元数据 → 论文身份与出版页链接。
2. [完成] 获取开放全文 → 记录文件、来源及版本。
3. [完成] 读取 reading-contract 指导，阅读正文与图表 → 页码证据表。
4. [未完成] 补充材料无法取得 → 相关实验细节未核实。
5. [完成] 基于已读证据梳理研究问题、方法、结果和结论的关系。

论文分析正文……
```

实际请求若只需摘要或已经给出全文，路线应相应缩短；不能复制示例作为真实执行记录。
